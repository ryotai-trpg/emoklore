# ロードマップ

現在はアルファ版（試作品）段階です。しばらくは互換性を気にせず破壊的な変更が続くと思います。

開発は以下の3フェーズで進めます。

## Phase 1: FoundryVTT v14対応

- [x] v14専用への移行（v13サポート打ち切り）— 完了（2026-07-19）

## Phase 2: リファクタリング

「動けばいい」で書いてきたコードを、適切な機能を適切な層に分離して責務をはっきりさせる形に書き換えます。設計方針と既知の課題は [アーキテクチャ](/architecture) を参照。

- [x] スキーマ定義の初期化順序依存（`CONFIG.EMOKLORE` / `game.i18n`）の解消
- [x] `EmokloreActor` から判定計算・ダイアログ・チャット生成を分離
- [x] シート層に混ざったルール計算を data 層へ移動
- [x] `as any` の削減（`noExplicitAny` を lint で `error` に）
- [x] 純粋関数（判定計算など）への vitest テスト導入
- [x] CSS・テンプレートのリファクタリング（部品と配置の2層化）

## Phase 3: 新機能

- キャラクターシートの機能追加・UI/UX向上
    - [x] UI設計の規約を明文化（`docs/ui-design.md`）
    - [x] 色設計の是正（全色をテキスト4.5:1／UI要素3:1に）
    - [x] ホバーとフォーカスの導入
    - [x] 英語表示の崩れ修正
    - [x] 編集の入力をスライダーから段のクリックへ
    - [x] 立ち絵と能力値をタブ共通の折りたためるサイドバーへ
    - 共鳴感情・技能選択にApplicationを用意
    - [x] アイテムタブ追加
    - [x] カスタム技能（Item `skill`）
    - **一般技能と基本技能の視覚言語を揃える** — 「名前／目標値／能力値アイコン」の並びと書体を両方で揃え、修得技能だけLvとバーを足す。密度の差（行とチップ）は情報量の差に由来するので残す。差を「別物」から「有無」にするのが狙い。編集モードのレベル表示をどう見せるかも一緒に決める
        - **`＊` / `★` の印をどこまで出すかもここで決める。** チャットの見出し・効果の適用先・カスタム技能の行には付けているが、組込技能の行にだけ付いていない。いまは「カスタム技能は名前をルールブックで引けないので区分が読めるのはそこだけ」という理由で差を残しているが、揃えるならこの機会に
    - UIの一貫性の残り（角丸の生値・`meter.css` の単位・経歴タブのstacked寄せ・`min-width` の妥当性）は、値の判断が要るものだけになっている（Issue #59）
    - 技能集のコンペンディウムを同梱する。いまは `packs` も LevelDB 化のビルド手順も無く、ユーザーがワールド内に作るぶんだけが動く。リリースワークフローごと決める必要がある
    - **ヘッダの再設計** — 名前・HP/MP・共鳴・感情3行の並びに一貫した論理がない。感情をプロフィールタブへ移す案と、名前とリソースを上下2段にする案がある。情報の置き場所を変えるので影響が大きく、案を固めてから着手する
- 武器・防具の実装
    - [x] 武器アイテムと武器シート
    - [x] 武器カード（1枚のカードに攻撃判定とダメージを積む）
    - [x] ダメージ適用（権限の無いアクターはGMのクライアントに委譲）
    - **ダメージ適用の結果を伏せられるようにする** — いまは「アクター名 HP: 16 → 8」を全員に見せている。敵のHPはPLに伏せたい情報なので、GMだけに見せるか、見せる範囲を設定で選べるようにしたい。`ChatMessage` の whisper とロールモードの扱いを一緒に決める（秘匿判定に対応していない #16 と同じ話）
    - 〈ストレングス〉による近接武器攻撃力の加算。`buildDamageFormula` の `bonus` に技能レベルを渡すだけ
    - 回避・防御によるダメージ軽減。`applyDamage` の `reduction` に寄せる
    - 防具。ルールブックに防具・防御力の規定が無いので、ハウスルールとして持つかを決めるところから
- NPC, 怪異用のキャラクターシート実装
    - 仕様を要検討。`npc` の登録を戻すときの注意は [アーキテクチャ](/architecture) の「既知の構造的課題」にある
- ハウリングカード実装
- イニシアチブ管理（本体の型付きCombatant（`Combat` / `Combatant` の `baseTypeAllowed`）の採用をここで検討する）
- FoundryVTT公式に登録
